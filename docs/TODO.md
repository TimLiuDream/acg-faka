## 老客推荐返现计划

状态：**待开发**

背景：目前客户群有 7 位客户，已经在群内告知老客户，成功介绍新客户购买后可以获得返现。现阶段继续手工登记，积累足够订单后再开发自动化功能。

关联规划：[获客计划](./customer-acquisition-plan.md)

### 已确定规则

- 推荐奖励面向已经完成购买的老客户。
- 被推荐人必须产生真实付款订单。
- 退款、关闭、重复客户和自邀订单不计算奖励。
- 奖励需要经过售后观察期后才能发放。
- 推荐关系和返现状态必须可以在后台查询。
- 返现规则发生变化时，已经产生的有效推荐按下单时的规则计算。

### 开发前待确认

- [ ] 每笔订单的返现金额或返现比例。
- [ ] 售后观察期具体天数。
- [ ] 奖励形式：现金、站内余额、优惠券或多种方式可选。
- [ ] 现金返现的发放渠道和最小提现金额。
- [ ] 哪些商品参与推荐计划。
- [ ] 老客户是否必须注册并绑定联系方式。
- [ ] 同一被推荐客户的后续复购是否继续计算奖励。

### MVP 功能

- [ ] 为符合条件的老客户生成唯一邀请码和邀请链接。
- [ ] 邀请链接支持 `ref` 参数，并在浏览器中保留首次有效推荐关系。
- [ ] 游客无需注册也能通过邀请链接下单。
- [ ] 创建订单时保存推荐人、邀请码和下单时的奖励规则快照。
- [ ] 支付成功后创建一条“观察中”的返现记录。
- [ ] 售后观察期结束后，将记录改为“可发放”。
- [ ] 管理员在后台确认发放，并记录时间、金额、方式和备注。
- [ ] 订单退款或关闭时自动取消未发放奖励，并标记原因。
- [ ] 个人中心展示推荐链接、有效邀请数、待发放和已发放金额。
- [ ] 管理后台支持按推荐人、订单号、状态和日期筛选返现记录。
- [ ] 付款、奖励可发放和实际发放时发送飞书通知。

### 防滥用要求

- [ ] 禁止推荐人邀请自己的账户或联系方式。
- [ ] 对相同联系方式、设备特征、IP 和支付标识进行风险提示，不直接依赖单一字段判定作弊。
- [ ] 同一新客户只能绑定一个首次有效推荐人。
- [ ] 管理员可以取消异常推荐关系，并保留操作记录。
- [ ] 金额计算使用定点小数，不能使用浮点数直接计算返现。
- [ ] 支付回调重复到达时不能重复创建奖励。
- [ ] 返现发放操作必须幂等，重复点击不能重复记账。

### 数据与统计

- [ ] 邀请链接访问量。
- [ ] 被推荐客户数。
- [ ] 推荐订单数及成交金额。
- [ ] 观察中、可发放、已发放和已取消的奖励金额。
- [ ] 每位推荐人的成交、退款和复购数据。
- [ ] 推荐渠道的实际获客成本和毛利。

### 页面入口

- [ ] 个人中心增加“推荐有礼”。
- [ ] 订单结果页增加推荐入口。
- [ ] 发货邮件和兑换成功页展示邀请链接。
- [ ] 管理后台增加“推荐返现”管理页面。
- [ ] 提供适合微信群转发的推荐文案和海报。

### 验收条件

- 一个新客户只能归属一个推荐人。
- 游客订单和登录用户订单都能正确保存推荐关系。
- 支付回调重试不会产生重复奖励。
- 退款订单不会得到奖励。
- 规则调整不会改变历史订单的奖励金额。
- 管理员可以完整追踪每笔奖励对应的推荐人、客户和订单。
- 返现统计金额与返现记录明细一致。

### 当前人工执行方式

自动功能上线前继续采用以下流程：

1. 新客户下单时备注推荐人的微信名。
2. 手工记录推荐人、订单号、订单金额和付款时间。
3. 确认订单完成并经过售后观察期。
4. 发放返现并记录金额、时间和渠道。
5. 退款或异常订单从记录中取消，并保留原因。
